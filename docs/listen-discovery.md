1. **Canonical eligibility.** Listen reuses `fetchBooksForPublic()` (the same catalogue as Read), loads its `chapters` by `book_id`, then loads `book_chapter_audio` rows with `is_published = true` for those chapter IDs. A book qualifies when at least one Arabic or English row has a supported source accepted by the existing playback source normalizer, or a valid YouTube ID. Queries are ordered, paginated and batched; errors are surfaced rather than silently becoming an empty catalogue. The live schema has no separate Book/Chapter publication flags, so no new publication rule was invented. Supabase query methods follow the [official select documentation](https://supabase.com/docs/reference/javascript/select).

2. **Fields.** Relations: `books.id`, `chapters.id`, `chapters.book_id`, `book_chapter_audio.chapter_id`. Availability: `language` (`ar` or `en`, with the existing legacy Arabic fallback), `is_published`, `source_type`, `storage_bucket`, `storage_path`, `external_url`, `external_video_id`. Existing `duration_seconds` and `narrator` remain player metadata. Existing canonical book ID, slug, title, author, cover and other Read metadata are reused. Both Listen cards and player use Read's full-cover `object-fit: contain` presentation.

3. **Static lists.** No production book-ID, slug or title allow-list was found controlling Listen eligibility, so none was removed. The existing database-driven implementation was retained and corrected. Fixed IDs in isolated test fixtures are synthetic test data only.

4. **Automatic discovery.** The first published valid source makes its existing book discoverable; either language suffices. Later audio chapters appear from the same tables. No duplicate books, separate audiobook catalogue, manual Listen assignment or alternate Storage resolver was introduced. Discovery remains available to normal users; existing AWM+ authorization still gates playback URLs.

5. **Invalidation.** Successful Admin audio save, publish/unpublish and reference removal immediately expire `books-public` with `updateTag`, and revalidate `/books`, the affected `/listen/{book}`, book and reader routes. Existing Admin book/chapter mutations already expire that shared tag. The 60-second audio cache TTL remains a backstop for changes outside Admin. Library/player clients merge fresh route data on visible-window focus/return and every 60 seconds while visible, coalescing events for five seconds and cleaning up on navigation. Caching is not globally disabled. When a chosen language disappears, the player falls back to a remaining language. Removing all sources makes the direct Listen route return not found instead of an empty player.

6. **Arabic-only verification.** A warm empty catalogue becomes populated after saving/publishing only Arabic audio through Admin; real private audio decodes and plays.

7. **English-only verification.** A book with only published English audio appears and plays without requiring Arabic audio. Unpublished Arabic does not count.

8. **Later chapters and partial audio.** Adding English audio to a later chapter updates an already-open player on its normal refresh. Each language lists only its actual chapter sources; unavailable combinations have no playback option. Unit coverage also exercises catalogue growth past 1,000 chapters.

9. **Removal/unpublish.** Unpublishing Arabic preserves a book that still has English audio. Removing its last published reference removes the book from the warm Listen catalogue. Removing references preserves underlying media objects. Invalid/unpublished references are excluded consistently from library, book and inline chapter availability.

10. **Deployment.** Future audiobook additions/removals require no rebuild or deployment once this fix is deployed. The production-mode browser tests mutate canonical fixture data through Admin after the build is already running. This implementation remains local; it has not been committed, pushed or deployed. Production content was only read, never changed.

11. **Files.** Production: `app/actions/audiobooks.ts`, `app/books/BooksLibrary.tsx`, `app/books/AudiobookPlayer.tsx`, `app/books/LibraryBookCard.tsx`, new `app/books/useBookCatalogueRefresh.ts`. Tests: new `app/actions/listenDiscovery.test.ts`, new `app/books/useBookCatalogueRefresh.test.tsx`, new `e2e/listen-discovery.pw.ts`, updated `e2e/fixture-server.mjs`; existing `app/actions/audiobooks.test.ts`, `app/actions/audiobooks.live.test.ts`, `app/actions/audiobookSources.live.test.ts` mocks now support tag invalidation. This report and responsive screenshots are under `docs/`.

12. **Database/RLS.** No schema, migration, RLS, entitlement, bucket or production data changes. A read-only live schema and eligibility audit found 40 published audio sources across five books, all 40 matching existing Storage objects. Admin already verifies uploaded object bytes before saving; discovery validates canonical source references without signing or exposing private audio. Remote media can still become unavailable later and retains the existing player error/retry handling.

13. **Validation.** All 78 targeted unit/regression tests across seven files passed. All 13 production-build Chrome browser tests passed in one final run: ten existing Admin/upload/playback/entitlement regressions and three complete discovery flows at 320, 768 and 1440px. TypeScript, changed-file ESLint, production build and whitespace checks passed. Tests cover warm-cache discovery, later chapters, removal/unpublish, invalid sources, pagination, refresh lifecycle/navigation cancellation, real audio decoding, private paths, full Storage URLs, HTTPS audio and YouTube references. Responsive discovery screenshots are saved in `docs/validation/listen-discovery/`. The initial browser attempts exposed fixture setup/timing problems and a refresh/navigation race; those were corrected before the final passing run. The simulated save-failure log in the retry test is expected. Production mutation tests are deliberately opt-in and were not run against real user content.
