# User management and content reviews

Inspection: 2 October 2026. Target: the supplied Next.js 16 / React 19 / MUI web workspace; the original brief mentions Flutter, which is not present here.

1. **Architecture:** App Router, cookie-backed Supabase Auth, guarded Server Actions using a private service client. Admin includes Shows, Books, Hans Wehr and Phrases. Existing content-version triggers support database sync; Next.js cache tags support web freshness.
2. **Accounts:** `auth.users` is the registered account source (12 at inspection). `public_profiles`, learning profiles and leaderboard profiles serve separate existing purposes; none is a complete account directory. Reuse Auth and public profile names rather than create another profile system. Only explicitly selected safe Auth fields leave the server.
3. **Premium:** existing `subscriptions` records; active/trialing with an unexpired period. Existing web policy also gives Admins Premium access. Preserve that policy and label included Admin access separately from paid subscription status. Do not change billing or invent renewal information.
4. **Admin authorization:** verified `auth.getUser()`, protected `app_metadata.role` / `is_admin`, plus server environment Admin IDs. Two metadata Admins exist. Canonical writes already use `guardAdmin()` and service-role queries. Move authorization to database role assignments, seed existing metadata Admins, and explicitly bootstrap configured Admin IDs before cutover if necessary. Do not retain an environment bypass after cutover.
5. **Roles:** protected assignments contain user/editor/admin, independent of subscriptions. Current database assignments determine privileges immediately; no user metadata authorization. Every privileged operation rechecks its actor. Last-Admin changes serialize in one transaction.
6. **Migration:** additive role assignments, access audit and content suggestions. Bootstrap existing protected metadata roles. Directory RPC joins Auth/profile/subscription data with server-side search, counts and bounded pagination. Preserve all existing users/content.
7. **Database security:** enable RLS on new tables; revoke direct client writes/deletes, including canonical content writes. Give authenticated users only own role and own suggestion reads. Server-only RPCs verify the server-authenticated actor independently. Preserve existing public canonical reads and existing guarded Admin Server Actions. Review storage separately; Editors receive no privileged content storage access.
8. **Screens:** this repository has no Flutter screens. Add `/admin/users`, `/admin/reviews`, `/reviewer`; extend Admin navigation and signed-in user navigation. MUI responsive forms/cards use existing design tokens.
9. **Reviews:** book lines are JSON blocks in `chapters.content`; show lines are JSON blocks in `episodes.transcript` (78 chapters and 113 episodes, all array format). Store parent identity, zero-based line index and full block snapshot. Compare the entire document snapshot too, so insertions/reordering cannot retarget a suggestion. Acceptance locks canonical row, validates snapshots, modifies only the selected block, records reviewer/status atomically and retains history. Arabic edits require structured tokens preserving dictionary metadata rather than flattening a line into an unannotated string. Comments never modify canonical content. Conflicts remain pending and show original/current/proposed content.
10. **Sequence:** schema/security and database tests; role integration; Users directory/details/audit; Reviewer book/show navigation and own suggestions; Admin review/filter/reply/accept/reject; regression tests, lint and production build. Test real PostgreSQL execution with the existing PGlite harness before applying the migration.

No account deletion is introduced. Role revocation retains attribution and suggestions. Deployment must apply the migration before enabling the new role checks; missing schema fails closed for privileged access.

## Verification and rollout

The migration was applied to the connected `arabicwithm` project. Verified counts after migration: 12 accounts, 2 Admins, 0 Editors, 3 Premium accounts (including Admin access), 78 chapters and 113 episodes. Direct authenticated canonical deletes, role updates, suggestion deletes and role-management RPC execution are denied. The private directory is not executable by anonymous clients.

Database tests execute the actual migration in PGlite PostgreSQL; Server Action tests verify authentication and actor binding. The final suite passed all 209 tests in 39 files. Production build, TypeScript and lint passed. Signed-out HTTP checks confirmed redirect markers and no Users/Reviewer screen exposure. A browser surface was unavailable, so authenticated visual QA remains a manual check after deploying the web changes.

Existing live Memory RPCs differ from repository migration versions and already validate caller identity; these were inspected and left unchanged. Advisor findings outside this feature were not changed. `access_change_audit` intentionally has RLS with no client policy and no client grants; the Admin server reads it after authorization.

### Manual check

Sign in as that Editor, open `/reviewer`, submit a comment or correction, edit/withdraw pending suggestions and inspect statuses. Sign in as Admin to reply, reject or accept from `/admin/reviews`. Arabic corrections require Admin-reviewed annotated tokens. When a source changes, acceptance stays blocked; request a fresh suggestion rather than forcing a stale overwrite. Deploy the web changes to expose these new screens on the hosted site; the database migration is already applied.
